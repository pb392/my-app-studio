Developer reference

One app. Two ways to use it.

The pages use HTML forms. The API uses JSON and HTTP status codes. The server enforces the same access rules for both.

GET /health returns public JSON. OpenAPI schema describes the routes actually implemented in this version.

{% if features.accounts %}
  • GET /api/csrf starts a pre-login session and returns a CSRF token.
  • POST /api/signup creates a member; POST /api/login signs in. Both accept username/password JSON and the X-CSRF-Token header.
  • GET /api/me returns the current user, or 401 when not logged in.
  • POST /api/logout revokes the current session. A copied old JWT must stop working.
    • {% if features.roles %}
  • GET /api/admin: anonymous → 401; member → 403; admin → 200.
    • {% endif %}

JWTs are signed, not encrypted. This app keeps them in an HttpOnly cookie and checks the current SQLite session and role on each protected request. Never put passwords or tokens in a URL.
